# 坑槽裂缝、边坡与桥涵咨询（开发草稿）

这是分析组织约定，尚未经工程专业审核。无预置安全限值、检测频率或施工参数；具体规范按实际对象逐次核验。支持和反证只引用当前有效的 known 事实；未知不是反证，未发现不等于排除。候选可以为空，不为凑报告而编造原因。

## 共同输出约定

选用下列 analysis_profile 后，answer.analysis_context 须包含该模板的所有文本字段，未查明的明确写“不清楚／待核查”及来源，不猜测补齐。每个 hypothesis 写 reasoning（事实如何支持推断及还缺什么）、discriminator（什么信息能区分）；每个 next_check 写 action、purpose、different_results（支持、不支持或仍未知时分别怎样推进）。

按通行与人员暴露、现象是否发展、最有区分价值的信息安排顺序。先给必要提示，再问一个关键问题，并写明不同答案会改变什么判断；用户不清楚或无法安全取得的信息转交专业核查，不反复追问。下一步写资料来源、核查目的及负责专业，不能暗示现场已经实施。

## 坑槽与裂缝：pavement-distress-v1

analysis_context：surface_type（沥青／水泥／未知）、distribution（车道、轮迹、接缝、旧修补等位置与分布）、depth_status（表面或涉及深层的已有证据；没有调查时保持未知）。混合沉陷、冒泥或快速变化时同时考虑隐蔽问题，不把所有开裂都当表面维修问题；沉陷主导另读 subsidence-consultation.md。

围绕已知现象选方向，而非默认列出全部原因：

- 表面材料损坏或旧修补界面问题待查：比对病害分布、路面类型、既有维修与照片时序；外观不能证明损坏止于面层。
- 水与排水异常参与待查：核对积水、渗漏、排水及出现时序；雨后出现只说明时间关系。
- 结构层或支撑状态变化待查：有沉陷、反复破损等线索时，交专业人员结合既有检测核定调查范围；未查明不能指定直接罩面或开挖。

先利用已有巡查、维修、路面结构和排水资料，说明不同调查结果会引向表层修复研究，还是进一步核查结构层、路基或设施。检测方法、深度、材料和参数由相应专业确定，不从裂缝照片推导承载力或安全限值。

## 边坡：slope-instability-v1

analysis_context：slope_type（土坡／岩坡／支挡或未知）、movement_scope（局部掉块还是坡体、支挡的变化线索）、drainage_relation（水路变化与异常的时间和空间关系）。不清楚地质和结构时，不把表面掉块与整体失稳混为同一问题。

沿现有 slope-water-movement 草稿卡区分局部松散、坡体／支挡变化及水相关方向。每项说明观测者、观测时间、位置及反证缺口；“清理完了”不代表上方稳定或风险解除。

不得要求用户到坡脚、裂缝旁、落石影响区检查或自行疏通。优先交接既有地质、防护设计、排水、巡查、降雨和监测记录；由相应专业判断调查及必要处置。出现持续掉块、裂缝或支挡变化等报告时，先提示停止暴露作业、报告管养单位并由相关单位组织管控；不等检索完成才提示。

## 桥梁与涵洞：bridge-culvert-v1

analysis_context：facility_type（桥梁或涵洞及已知结构类型）、component_location（构件、部位、方向和位置）、associated_changes（伴随变形、渗水、剥落或历史对比及其未知项）。设施不明时先确认对象，不能因 domain=bridge 就套用桥梁条文到涵洞。

沿现有 bridge-crack-observation 草稿卡区分材料／环境表面缺损、受力或构造变化、连接／支座／基础等关联方向。涵洞另考虑已有洞身、接缝、洞口、水路与路面异常资料的对应关系；并非要求用户进入涵内检查。

不凭裂缝单图作技术评级、承载力、安全或加固结论。优先整理结构图、既有检查和维修记录、同位置历史照片；专项检查项目由具备相应能力的单位核定。不要求用户进入高处、水中、桥下危险区或涵内测量。先处理异常对通行及人员的暴露，再交接设施管理单位及相应检查、检测、设计专业。

## 续办

收到纠正或新资料后重新分析；旧候选减少不代表病因已经排除。记录区分用户陈述、图片观察、报告记载及系统假设。程序只验证字段与事实引用，不验证工程判断正确性。
