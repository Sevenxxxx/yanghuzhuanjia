# ADR 0004：界面视觉遵循 Apple 设计体系

日期：2026-11-12。适用于 [ADR 0003](0003-chat-frontend.md) 的纯聊天前端（[page.html](../../scripts/p3/chat/page.html)）。这是视觉规范，不改交互与协议。

## 决定

界面按 Apple Human Interface Guidelines 组织：系统字体、语义色、系统蓝、连续圆角、毛玻璃的导航与输入栏、深浅色自适应。所有取值集中在前端 `<style>` 顶部的 token 区，组件只引用 token。

| 维度 | 取值与做法 |
|---|---|
| 字体 | 系统字体栈：`-apple-system`、`SF Pro Text`、`PingFang SC`，Windows 回退 `Microsoft YaHei`；**正文 14px／1.55**（对齐 dsh 的 `--dsh-content-font-size` 默认值，见下），次要 13px，脚注 12px，过程行 12px（细节用等宽 11.5px） |
| 颜色 | 语义色：`--label`／`--label-2`／`--separator`／`--fill-3`／`--fill-4`；强调色用系统蓝 `#007aff`（暗色 `#0a84ff`）；危险色 `#d70015`／`#ff453a`。禁止在组件里写死颜色 |
| 形状 | 连续圆角：控件 10px、卡片 16px、气泡 18px（用户气泡右下 6px 收口）、输入栏 24px 胶囊 |
| 材质 | 导航栏与输入栏用半透明底 + `backdrop-filter: blur(20px) saturate(180%)`，并提供不透明回退 |
| 布局 | 单列居中，最大 44rem；间距 8／10／16 的少量档位；空态与提问卡片居中成组；标题栏右侧固定一个「新对话」药丸按钮（13px、蓝色、`--fill-4` 底），标题保持居中 |
| 对话 | 用户消息右对齐蓝色气泡（iMessage 式），助手回答为无气泡正文；图片圆角 14px |
| 表格 | Markdown 表格渲染成卡片式表格：13px、圆角 12、表头 `--fill-4` 底与次要色、行间 1px 分隔线、容器随内容收缩、窄屏横向滚动 |
| 行内标记 | 支持粗体、行内代码、`<sub>`／`<sup>` 上下标（规范里的 `L<sub>k</sub>`）；只放开这两类标签，其余 HTML 一律按文字显示，代码块内的标记不渲染 |
| 滚动 | 自己发消息后强制贴到底部；回答流式追加时只在原本已贴底的情况下跟随；手动往上翻过就不再把你拽回底部 |
| 过程 | 回答上方按时间顺序列出「上下文注入 / 思考 / 工具调用」，12px 次要色、工具目标用等宽字体省略号截断；运行中自动展开并显示已用时间，本轮结束后折叠成一行「已完成，用时 X 分 Y 秒」，第二行摘要「执行了命令 ×2、文件 ×4…」；点标题展开或收起，单条「思考」也可点击展开全文 |
| 控件 | 触控目标 ≥32px（桌面）与 44px（移动端可用）；主操作是蓝色圆形发送键，附件是「＋」 |
| 深色 | `prefers-color-scheme` 全套语义色替换；控件底色单独用 `--control-fill`，避免与卡片同色而隐形 |
| 可访问性 | `:focus-visible` 蓝色描边、`prefers-reduced-motion` 关闭动画与过渡、按钮均有 `aria-label`、状态区 `aria-live` |
| 图标 | 只用内联 SVG 线条图标，不引入图标库或字体图标 |

## 渲染能力（模型回答的排版子集）

单文件页面不引入 Markdown 库，自己实现一个小解析器；下面是它认的结构与刻意不做的部分。改动这个清单时同步 `scripts/p3/chat/page.html` 的 `format()` 与本表。

| 结构 | 行为 |
|---|---|
| 标题 `#`～`######` | 统一渲染成三级标题样式 |
| 段落、空行 | 分段 |
| 无序列表 `- * •` 与有序列表 `1.` `1)` | `<ul>`／`<ol>`，按缩进支持嵌套（嵌套列表落在上一级 `<li>` 内） |
| 任务列表 `- [ ]`／`- [x]` | 显示为 ☐／☑，不生成可点击控件 |
| 引用 `>` | `<blockquote>`，左侧竖线、次要色 |
| 分隔线 `---`／`***`／`___` | `<hr>` |
| 表格 | 表头 + 分隔行；单元格支持 `\|` 转义竖线与 `<br>`；列对齐标记忽略 |
| 代码块 | 围栏 ` ``` ` 与 `~~~` 都支持；行内代码 `` `x` `` |
| 粗体／斜体／删除线 | `**`／`__`、`_斜体_`（限词边界，`file_name_here` 不会被误判）、`~~删除~~` |
| 链接 `[文字]（url）` | 仅 `http(s)://` 与 `mailto:`，且不含引号／空白；其他降级成「文字（URL）」纯文本 |
| 图片 `![说明]（url）` | **降级为链接**，不自动加载远程图片（避免把来源 IP 暴露给回答里出现的任意域名） |
| HTML 标签 | 只放开 `br sub sup b strong i em del`；其余标签（含 `<script>`、`<ul>`）一律按文字显示 |
| 上下标 | `L<sub>k</sub>`、`x<sup>2</sup>` 正常渲染 |

已知不做 / 会原样显示：

- 其他 HTML 块级标签、`<table>` 手写 HTML；
- LaTeX 公式、脚注、定义列表、setext 标题（用 `===` 划线的标题）、四空格缩进代码块；
- 表格列对齐（`:---:`）与单元格内多行；
- 未闭合的 `**`、`_` 等按字面显示。

## 为什么

- 用户在 Windows 上也要用，但界面要对标他熟悉的 Apple 观感；HIG 的语义色与系统字体让深浅色、字体回退、可读性都有明确依据，不用每次临场决定。
- token 化之后，改主色或圆角只动一处；此前样式里散落过硬编码颜色，改一次要翻整个文件。
- 与 ADR 0003 的「自有页面」一致：我们没有宿主样式要兼容，可以整套按 HIG 落地。

## 与 HIG 的一处刻意偏离

正文用 **14px** 而不是 HIG 的 17pt 正文：用户明确要求「字号和 dsh 原来一样」，而 dsh 的对话内容默认就是 `--dsh-content-font-size: 14px`（`ui-theme/theme-settings.ts`，可在 10–22px 之间调）。其余比例仍按 HIG 的尺度关系（标题 15px、脚注 12px）。

## 验证方式

用 Chrome headless 截图核对三种状态：桌面 1200×760（浅色／深色）、390px 宽（手机版），并检查提问卡片、选项、输入栏、空态。截图只作观感核对，不代替真机。

## 已知限制

- 未在真实 iPhone/iPad 上验证；Windows 上没有 SF Pro，回退到 Microsoft YaHei，观感与 macOS 有差异。
- `backdrop-filter` 与 `color-mix` 需要较新的 Chromium／Safari；已为两者提供不透明底色回退。
- 触控目标的 44px 只在移动端宽度下通过内边距近似达成，未做逐控件测量。
