# 当前限制

1. 5张知识卡与风险规则均为草稿；没有真实闭环案例、专业审核或用户反馈。流程测试不证明诊断准确率。
2. 程序核对定位、指纹、归属和字段，不能证明真实看图、完整适用性或专业审核身份；自由文本中的所有错误数值和过度结论不能自动检出。
3. 复杂否定、时间、口语及模糊部位可能误读，Codex 需补结构化观察。未命中不等于安全。
4. 规范覆盖和有效性未全面核查，存在 OCR 与旧置信度，只能逐页复核；read 无统一 JSON，保存原始输出与提示。
5. 自动技能目录热刷新未独立观察，显式读取和调用已验证。本 CLI 不能约束宿主全部工具，不是共享产品隔离层。
6. 默认路径对应当前 Windows；换机需配置。渲染复用已有 PyMuPDF，未测其他系统、dsh 后台或多用户。
7. 本地版本与 SHA-256 不提供加密、身份认证或抗恶意篡改签名。备份需安静窗口，异常锁先人工确认，不自动删除损坏数据。
8. 案例库为空，流程用隔离样例测试，未验证真实召回和借鉴效果。发布声明依赖真实人工审核。
9. 没有独立盲评的通用模型对照，不能声称答案必然优于直接问模型；已有的是工具可追溯性与流程验证。
10. 不含自动现场照片诊断、结构计算、dsh 后台、页面或部署；0.1.4可由宿主实际看图并记录可见现象，不能据此证明隐蔽病因或安全；没有全局安装或修改其他客户端配置。
11. 0.1.1 的待答问题、答复与恢复摘要由本地工具保存；弹窗显示和真实提交仍依赖宿主。submitted 字段是宿主声明，不是身份或实际点击证明；复杂自由文本仍需 Agent 核对。
12. 沉陷分析模板检查内容字段和事实引用，不能自动判定病因推理正确。恢复摘要中的候选增减是文字记录变化，不代表工程原因已确认／排除；核查完成情况仍须按真实资料补录。
13. Windows 存储兼容仅接受经文件身份核对的 LocalCache 对应路径，保留系统合并视图；未覆盖其他重定向机制、其他用户或所有 Windows 打包环境。新的非预期路径仍会报错，不自动搬移记录。
14. 0.1.2 默认临时状态仍会短期写入本地，最后写入24小时后由后续工具调用清理，没有后台定时删除；显式结束可立即清理。临时状态清理后不能按编号恢复。用户要求导出的文件保留；此策略不管理 Codex 聊天记录、原始附件或已单独交付的文档。
15. 0.1.3 的坑槽裂缝、边坡及桥涵分析与三种交付格式检查内容结构，不验证病因、检测方案、部门职责或所有正文规范判断。无独立工程专业审阅；专项文件为沟通草稿。0.1.4增加按需Word。旧无 analysis_profile 的接口仍可读取和使用，不能宣称程序强制覆盖所有宿主回答。
16. 照片登记不代表实际看图，viewed与观察者是宿主声明，程序不能证明视觉推理正确。照片位置、拍摄时间、方向是用户提供的未经核实信息；不读取GPS、不自动外发。不支持照片自动测量、隐蔽病害识别、发展趋势判定或安全许可。
17. Word只在明确请求时生成，附图另须明确要求；默认文档依赖本机Codex捆绑Python及python-docx，换机需配置并复测。导出返回待渲染核对，CLI本身不启动Word或安装软件；宿主负责实际渲染和逐页检查。本机验证可用Microsoft Word转PDF替代缺失的LibreOffice渲染器。
18. 方向比较只核对字段与事实引用；不自动验证机理、效果、经济性、工期或所有文字判断，不进行评分和施工审批。缺证据时须保留未知并交专业核定。
19. 0.1.5交付检查可阻止明确过时、失效引用或照片异常；数值／条文仅作直接文字匹配，不自动换算单位，不证明测量、版本现行性和工程含义正确。正文与比较表的检测只覆盖部分明确选用措辞，复杂否定、条件、例外及隐含矛盾仍须宿主核对。告警有字段定位，不能把没有告警当作一致性审核或专业验收通过。
20. 普通 export 必须通过最新意见有效性检查，但完整咨询 JSON 仍含原话和历史，Markdown／Word 可能含续办与前次意见；专项交付按用途裁取。history_only 仅在明确追溯要求下生成带历史标注的完整 Markdown／JSON，不是脱敏开关。检查内容指纹绑定选定范围及实际核验时的来源状态，不保证外部源文件此后一直不变。照片字节与图注检查不证明照片解释正确或 Word 排版合格。
21. 所有 CLI 请求分派前均执行既定过期清理，包括 doctor 和 delivery-check。“检查只读”不表示整个调用无清理副作用；check_trial 在清理之后比较剩余默认 JSON 指纹，不验证清理前后所有文件不变。
22. 示例配置中的 privacy_default 当前未被读取，实际新咨询默认 restricted／external_model_allowed=false。集成脚本没有统一的 --config 入口，换机不能仅配置 CLI 后便声称所有检查已适配。默认存储依赖项目绝对路径，换目录后需核对原存储位置。
23. 0.1.6 的 decision_impact 是文字性判断，不是定量信息价值或工程结论；程序只检查 question-ask 逐题对应、非空和长度，不验证分支是否正确、问题是否最优，也不保证已问到关键点。briefing 的默认提示是通用模板，须结合本例改写，不能当作本例结论。
24. 0.1.7 的案例库支持候选、审核和引用门槛；2026-11-05 用户要求清理全部案例，当前 `data/cases` 为空（仅保留空索引）。候选案例未经人工审核，不能证明病因、处治效果或适用性；程序只检查结构、来源字段和证据状态，不验证内容真实性。候选案例不得写入 case_refs，也不得当作工程依据。
25. 0.1.8 的本地资料库（`data/library/`）整体 gitignore，仅本地保存；当前 7 条：0007 会议论文（`case_source`）＋6 篇开放获取论文，尚无教材，教材需用户提供合法 PDF。资料库只支持文本型 PDF，按页文本、字面检索和 PDF 渲染；不解析表格／公式／扫描件，不做 OCR、自动摘要或外发。论文的工程适用性和结论未独立复核；原文不是规范或审核结论，检索命中不证明原文支持当前工程判断；版权和许可由使用者核对。

## 0.4.0 服务器试用版（Windows Server 2022）

1. **只有共享口令，没有账号体系**：所有同事共用一个密码；没有按人数据隔离，同一 `roadchat`
   账户下 agent 理论上能读到其他访问者的目录。真正的隔离（每账号独立 OS 用户/容器）留到 v2。
2. **试用期可以是纯 HTTP**：`deploy.json` 的 `https=false` 时口令与对话内容在链路上是明文，
   只适合内部短期试用；切 HTTPS 只需改配置重跑 `install-chat.ps1`。
3. **停止只影响自己**：停止键重启该访问者的运行时（约 10–20 秒），不影响别人；这是他自己的代价。
4. **空闲回收 30 分钟**：某访问者连续 30 分钟没有请求就停掉他的运行时（会话留在磁盘，下次说话
   自动 `session/resume`，代价是第一条消息等 15–20 秒）。可用 `ROAD_CHAT_IDLE_SECONDS` 调整，0 关闭。
   同一访问者累计 8 个新对话后重建运行时；服务每天 04:00 重启一次。
5. **并发上限按「在线」算**：最多 8 个人同时有运行时。第 9 个**同时在线**的人会收到
   「暂时已超过使用人数上限（8人），请稍后再试」；空闲被回收、或只是打开过页面的人**不占名额**。
   上限写死在 `ChatService.MAX_VISITORS`，不静默踢掉在线者。
6. **聊天页没有文件下载**：Word 交付不在本期范围，页面只能看文字与图片。
7. **未在真实服务器验收**：`acceptance.ps1`、攻击演练、`guifanchaxun` 在服务器上的首次运行、
   nginx/Caddy 与证书都还没跑过；本机验证不能替代真机验证。
8. **隔离边界是 OS 账户**：能保证改不了仓库与系统文件、拿不到真实 API key、出网受主机防火墙限制；
   不能保证 agent 不执行命令或读它权限内的文件。
9. **部署脚本只支持 Windows**：Linux 版脚本已从仓库移除（从未验证）；改回 Linux 需要重做部署层。
