# 道路养护 AI 技术专家 · 个人试用版

在现有 Codex 中提供多轮养护咨询、风险线索检查、规范回源和按需交付。知识卡与风险规则尚未经工程专业审核，当前能力与版本见 [开发交接](docs/交接.md)。

开发接手先读 [AGENTS.md](AGENTS.md) → [开发交接](docs/交接.md)；产品目标与路线见 [总体方案](docs/道路养护%20AI%20技术专家——项目总体方案与%20Codex%20开发交接文档.md)。

## 开始与继续咨询

在聊天中说：

> 使用 road-diagnosis 项目技能，开始一次养护咨询。这是允许当前模型处理的脱敏描述：……。先给简短重点，再给完整分析。

描述设施、现象、发现时间和变化即可，不知道的保留未知，无需手写 JSON。需要补充时通常先弹窗问一个关键问题，并说明不同回答会改变什么判断；不支持弹窗或你偏好文字时改用正文。未回复或未提交的预选项不会被当作事实，已说明无法提供的信息不反复追问。照片和文件通过聊天附件提供。

同一问题可以直接说“继续刚才的咨询，补充信息是……”。回答会说明候选解释、支持与反证、证据缺口、下一步核查及不同结果的影响；紧急提示先行。新信息使旧意见过时时，需要重新分析。

## 可以获得什么

| 需要 | 可以怎么说 | 输出边界 |
|---|---|---|
| 分析病害 | “分析这处沉陷／坑槽裂缝／边坡／桥涵异常” | 保留未知与条件，不确认隐蔽病因或通行安全 |
| 查看照片 | 附上获准照片，可补充位置、时间和方向 | 实际看图后记录可见现象；受控副本去除 EXIF/GPS，原图不改动 |
| 比较方向 | “比较后续处理方向，说明前提和证据缺口” | 不自动评分或批准施工 |
| 参考案例 | “有没有类似的沉陷／塌陷案例” | 只有审核通过的案例可引用；公开候选标注未审核，只作背景 |
| 查资料原文 | “查教材／论文里关于……的说法” | 仅本地资料库，按页查；规范仍回源，原文不等于结论 |
| 专项草稿 | “整理现场处置建议／检测委托要点／部门回复” | 默认聊天交付，属于待核对草稿 |
| 文件交付 | “导出这次意见”；需要 Word 时明确说明 | Word 附图另须明确要求，生成后还要渲染核对 |
| 检查意见 | “交付前检查这份意见” | 检查过时与失效引用等；未发现问题不代表全文或工程审核通过 |

真实案例库允许为空；当前案例库已清空。公开资料形成的候选案例只作背景线索，未经人工审核不作为依据，也不能写入规范或案例引用。教材、论文和案例原文放在本地资料库，可按页查；原文不提交 Git，仅本地研究与审核使用。规范先查本地，重要证据缺口再查官方网络，仍不足才查可信第三方。

## 临时状态、保存与导出

默认仅保留当次临时状态，最后写入 24 小时后由后续调用清理，没有后台定时删除。说“结束这次咨询”会立即清理未保存状态及关联副本；原附件、原规范和明确导出的文件保留。临时状态仍会短期落盘，过期或结束后不保证跨聊天恢复。

长期留存时说“保存这次咨询”，成功后才提供编号；之后可以说“列出已保存咨询”或“恢复咨询编号……”。恢复会说明旧意见、新信息、纠正、待答与核查缺口，不假定调查已经完成。

导出不自动保存整次咨询。普通完整咨询 JSON 仍含原话和历史，Markdown／Word 可能含续办与前次意见；专项文件按用途输出。历史追溯须明确要求，并标注不作为当前意见交付；历史模式不是脱敏功能。分享文件仍须符合资料权限。

用户主动提供描述不自动授权读取其他本地文件。受限记录默认不向当前模型返回原文；本项目没有模型 API 或网络上传代码，宿主权限仍按实际配置管理。
